# Qala Balance AI

**«Аким на 5 часов»** — сценарный симулятор городского бюджета для кейса Astana Innovations на HackAlem AI.

> Сценарное планирование городского бюджета с прозрачной оценкой последствий.

Проект показывает, как набор управленческих решений может изменить условные показатели районов. Это демонстрационная модель на **синтетических данных**, а не официальный расчёт или прогноз будущего Астаны.

## Проблема и решение

Бюджетные решения приходится сравнивать сразу по нескольким направлениям: транспорт, зелёные зоны, социальные объекты, безопасность и городские сервисы. Улучшение одного показателя может стоить дорого, затронуть не все районы или иметь побочный эффект. Qala Balance AI делает эти компромиссы видимыми: пользователь собирает сценарий из пяти инициатив, получает воспроизводимый расчёт и понятное объяснение результата.

## Как пройти сценарий

1. Изучите исходное состояние пяти условных городских зон.
2. Выберите **ровно одну** инициативу в каждой из пяти категорий.
3. Следите за единым бюджетом **1 000 млн ₸**. При перерасходе расчёт блокируется; можно заменить дорогую меру.
4. Запустите симуляцию и сравните бюджет, Score и показатели районов до и после.
5. Прочитайте анализ сильных сторон, рисков и компромиссов. Измените выбор и пересчитайте сценарий либо начните заново.

## Возможности

- Одинаковый стартовый бюджет и исходные данные для всех пользователей.
- Пять категорий и 15 инициатив: по три на каждую категорию. У каждой есть цена, целевые районы, численные эффекты и риск.
- Автоматический расчёт расходов и остатка, запрет сценариев дороже 1 000 млн ₸.
- Детерминированный Astana Quality of Life Score от 0 до 100 и сравнение до/после.
- Изменения по направлениям и районам, включая ухудшения.
- Серверный анализ через OpenAI с проверкой ответа. Без ключа или при сбое API возвращается содержательный локальный анализ.
- Подбор одной доступной замены, способной повысить Score; для перерасхода модель также умеет искать доступный план с минимальным числом замен.

## Быстрый запуск

Требуются Node.js 22 или новее и npm (актуальный OpenAI SDK требует Node.js 22+). Из корня репозитория:

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Next.js (обычно `http://localhost:3000`). Ключ OpenAI **не обязателен**: без него используется детерминированный fallback.

Для AI-анализа создайте локальный `.env.local` на основе `.env.example`:

```env
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

`OPENAI_MODEL` необязателен; по умолчанию используется `gpt-4o-mini`. Храните ключ только в `.env.local` или переменных окружения сервера. Файлы `.env*`, кроме `.env.example`, исключены из Git. Ключ не отправляется в браузер.

## Архитектура и технологии

Приложение использует **Next.js App Router, React, TypeScript, CSS и официальный OpenAI JavaScript SDK**. База данных и авторизация не требуются. Исходные данные живут в локальных TypeScript-модулях; расчёт не зависит от языковой модели.

```text
src/
  app/
    api/analyze/route.ts   POST-анализ, серверный OpenAI и fallback
    page.tsx               пользовательский сценарий
    layout.tsx             корневой макет
    globals.css            адаптивные стили
  components/              карточки, бюджет, районы, результаты и анализ
  data/
    districts.ts           исходные условные показатели районов
    initiatives.ts         каталог инициатив
  lib/
    scoring.ts             формула Score
    simulation.ts          выбор, бюджет, эффекты и варианты замены
    fallbackAnalysis.ts    объяснение без API
  types/simulation.ts      общие типы клиента и сервера
```

Интерфейс локально вызывает `simulate(selection)` для мгновенного результата. Для объяснения он отправляет на `POST /api/analyze` **только идентификаторы выбранных инициатив**:

```json
{ "selection": { "transport": "bike-network", "greenery": "courtyard-trees", "social": "mobile-clinics", "safety": "street-lighting", "services": "service-kiosks" } }
```

Сервер заново проверяет выбор и пересчитывает сценарий, поэтому не доверяет присланным из браузера суммам или Score. Успешный ответ имеет вид `{ "analysis": { "summary": "...", "strengths": ["..."], "risks": ["..."], "tradeoffs": ["..."], "recommendation": "..." }, "source": "openai" }`. При отсутствии ключа или ошибке модели `source` равен `fallback`; при некорректном выборе сервер возвращает ошибку 400/422.

## Синтетические данные

Модель содержит пять условных зон с узнаваемыми названиями: **Есиль, Нура, Алматы, Сарыарка, Байконыр**. Для каждой хранятся значения от 0 до 100 по транспорту, озеленению, социальной инфраструктуре, безопасности и сервисам. Числа созданы для демонстрации; они не являются официальной статистикой. Эффекты инициатив применяются только к указанным зонам, затем ограничиваются диапазоном 0–100. Некоторые эффекты отрицательны, поэтому ухудшения видны в результатах.

## Формула Astana Quality of Life Score

Формула в `src/lib/scoring.ts` не использует OpenAI. Сначала для каждой зоны рассчитывается взвешенный показатель:

```text
zoneScore = 0,25 × transport
          + 0,16 × greenery
          + 0,24 × social
          + 0,20 × safety
          + 0,15 × services
```

Затем берётся среднее `zoneScore` всех зон. Разница между максимальным и минимальным `zoneScore` больше 20 пунктов создаёт небольшой штраф:

```text
gap = max(zoneScore) − min(zoneScore)
penalty = max(0, gap − 20) × 0,1
Score = roundToOneDecimal(clamp(mean(zoneScore) − penalty, 0, 100))
```

Исходные и итоговые метрики ограничиваются диапазоном 0–100, итог округляется до одного знака. При изменении выбранных инициатив меняются метрики и, как следствие, Score. `districtDeltas` отражает разницу взвешенного показателя отдельной зоны; общий Score дополнительно учитывает штраф за неравенство.

## Роль OpenAI и устойчивость

Сервер использует **Responses API** и Structured Outputs с JSON Schema согласно [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs). Модель получает уже вычисленные затраты, Score, изменения зон, риски инициатив и проверенную кодом рекомендацию. Она объясняет результат по-русски, не пересчитывает бюджет и не должна добавлять факты, которых нет во входных данных. Ответ дополнительно проверяется программно. Текст рекомендации всегда подставляется из детерминированного расчёта, чтобы он не предлагал перерасход.

Если `OPENAI_API_KEY` отсутствует, сеть недоступна, модель отказала или вернула неподходящий ответ, тот же endpoint возвращает fallback. Он строит описание непосредственно из результатов симуляции и не требует внешнего сервиса. Некорректный или слишком дорогой сценарий не отправляется в OpenAI.

## Пример для демонстрации жюри

Выберите **«Связанная велосеть»**, **«Деревья во дворах»**, **«Мобильные медпункты»**, **«Освещение улиц»**, **«Сервисные пункты»**. Расход составит **610 млн ₸**, остаток — **390 млн ₸**. На текущем наборе данных Score изменится с **59,9 до 67,3**. В результатах будут видны изменения по каждой категории и зоне. Затем замените одну инициативу и покажите, что бюджет и Score пересчитываются.

## Ограничения и дальнейшее развитие

Модель показывает условные относительные эффекты и не учитывает реальные сроки строительства, обслуживание на годы вперёд, инфляцию, нормативные ограничения или причинные зависимости. Названия зон узнаваемы, но показатели и стоимость инициатив **синтетические**. Результат нельзя использовать как основание для реальных бюджетных решений.

Следующий шаг — подключение проверенных открытых городских данных, паспортизация источников и обновление показателей по годам. Можно добавить настройку весов с публичным обсуждением, сравнение нескольких сценариев, чувствительность результата к допущениям, карту зон и экспорт отчёта. Перед использованием в реальном управлении потребуются методологическая проверка и участие профильных экспертов.
